# REST API

Design of the backend REST API. Once implemented, the OpenAPI spec generated by springdoc (`/v3/api-docs`, UI at `/swagger-ui.html`) is the source of truth for exact schemas; this document is the design contract and explains behaviour.

Status values: **Implemented**, **In progress** (partially implemented) or **Planned** (designed, not implemented).

## Conventions

| Topic | Convention |
|---|---|
| Base path | `/api/v1`. Breaking changes go to `/api/v2`. |
| Format | JSON, UTF-8, `camelCase` properties. Unknown properties in requests are rejected. |
| Identifiers | Only UUIDs are exposed (`id` fields are the database `uuid` columns). Restaurants are also addressable by `slug` on public endpoints. |
| Resource names | Plural nouns: `/bookings`, `/tables`. |
| Actions | State changes that are not simple field updates use `POST` on a sub-resource: `POST /bookings/{id}/cancel`. |
| Updates | `PATCH` with only the fields to change. `PUT` only to replace a whole collection (e.g. weekly opening hours). |
| Dates and times | RFC 3339 with offset (`2026-11-21T20:00:00-03:00`). Responses use the restaurant's offset. Dates alone: `YYYY-MM-DD`. |
| Pagination | `?page=0&size=20` (max 100). Response: `{ "items": [], "page": 0, "size": 20, "totalItems": 57, "totalPages": 3 }`. |
| Sorting | `?sort=startsAt,asc`. |
| Idempotency | `POST` endpoints that create bookings accept an `Idempotency-Key` header (UUID). Repeating a request with the same key within 24 h returns the original response. |
| Concurrency | Admin `PATCH` on settings, tables and bookings accepts `If-Match` with the resource's `version`; a stale version returns `412`. |
| Rate limits | Responses carry `RateLimit-Limit`, `RateLimit-Remaining` and, on `429`, `Retry-After` (NFR-06). |

## Authentication

| Scheme | Header | Who | Obtained from |
|---|---|---|---|
| None | — | Anyone | — |
| Booking token | `X-Booking-Token: <token>` | Holder of a management link | Management link in booking emails |
| Customer session | `Authorization: Bearer <jwt>` | Customer who verified their email | `POST /customer-auth/token` |
| Staff | `Authorization: Bearer <jwt>` | Owner, Host, platform admin | `POST /auth/login` |

Admin endpoints are under `/admin/restaurants/{restaurantId}` and check the caller's role **in that restaurant**. A staff user who is not a member gets `404` (not `403`), so restaurant IDs cannot be probed.

## Errors

Errors use [RFC 9457 Problem Details](https://www.rfc-editor.org/rfc/rfc9457) (`Content-Type: application/problem+json`) with an extra `code` for the frontend and, for validation errors, a list of `errors`.

```json
{
  "type": "https://docs.example.com/errors/table-not-available",
  "title": "Table not available",
  "status": 409,
  "code": "TABLE_NOT_AVAILABLE",
  "detail": "Table T12 is already booked at 2026-11-21T20:00:00-03:00.",
  "instance": "/api/v1/restaurants/cantina-da-praca/bookings",
  "requestId": "3f9a…"
}
```

| HTTP | `code` | When | Rule |
|---|---|---|---|
| 400 | `VALIDATION_FAILED` | Malformed or invalid fields (`errors: [{ "field": "partySize", "message": "must be ≥ 1" }]`) | — |
| 401 | `UNAUTHENTICATED` | Missing, invalid or expired token | — |
| 403 | `FORBIDDEN` | Authenticated but the role is not allowed (inside a restaurant the user belongs to) | — |
| 404 | `NOT_FOUND` | Resource does not exist or is not visible to the caller | NFR-08 |
| 409 | `TABLE_NOT_AVAILABLE` | Table or combination taken (including a concurrent request) | BR-02 |
| 409 | `INVALID_STATE_TRANSITION` | Action not allowed in the booking's current status | Lifecycle |
| 409 | `TABLE_HAS_UPCOMING_BOOKINGS` | Deactivating/deleting a table or combination with upcoming bookings | BR-50 |
| 409 | `LAST_OWNER` | Removing or demoting the last Owner | BR-54 |
| 410 | `VERIFICATION_EXPIRED` | Hold expired before the code was entered | BR-30 |
| 412 | `VERSION_MISMATCH` | `If-Match` does not match | — |
| 422 | `OUTSIDE_OPENING_HOURS` | Start/end outside opening hours or inside a closure | BR-04, BR-05 |
| 422 | `INVALID_SLOT` | Start not aligned to the slot interval | BR-03 |
| 422 | `LEAD_TIME_NOT_MET` / `TOO_FAR_IN_ADVANCE` | Online booking too soon / too far ahead | BR-07 |
| 422 | `PARTY_SIZE_NOT_ALLOWED` | Party does not fit the table or exceeds `maxPartySize` | BR-06, BR-07 |
| 422 | `TOO_MANY_ACTIVE_BOOKINGS` | Customer reached `maxActiveBookingsPerCustomer` | BR-10 |
| 422 | `INVALID_CODE` | Wrong verification code (`attemptsRemaining` included) | BR-16 |
| 422 | `INVALID_SETTINGS` | Settings break a validation rule | Settings |
| 429 | `RATE_LIMITED` | Too many requests | NFR-06, BR-16 |
| 500 | `INTERNAL_ERROR` | Unexpected error (details only in server logs) | — |

## Public endpoints

### `GET /restaurants/{slug}/availability/slots`

Start times with at least one fitting, free table or combination (FR-02).

`GET /api/v1/restaurants/cantina-da-praca/availability/slots?date=2026-11-21&partySize=4`

```json
{
  "date": "2026-11-21",
  "timeZone": "America/Sao_Paulo",
  "partySize": 4,
  "bookingDurationMinutes": 120,
  "slots": [
    { "startsAt": "2026-11-21T19:00:00-03:00", "availableOptions": 5 },
    { "startsAt": "2026-11-21T19:30:00-03:00", "availableOptions": 2 },
    { "startsAt": "2026-11-21T20:00:00-03:00", "availableOptions": 0 }
  ]
}
```

Slots with `availableOptions: 0` are returned so the UI can show them as full.

### `GET /restaurants/{slug}/availability/tables`

Every table and combination with its state for one start time (FR-03). The floor-plan geometry comes from `GET /restaurants/{slug}/floor-plan` and can be cached by the frontend.

`GET /api/v1/restaurants/cantina-da-praca/availability/tables?startsAt=2026-11-21T19:30:00-03:00&partySize=4`

```json
{
  "startsAt": "2026-11-21T19:30:00-03:00",
  "endsAt": "2026-11-21T21:30:00-03:00",
  "tables": [
    { "id": "0b6e…", "label": "T1", "seats": 2, "state": "TOO_SMALL" },
    { "id": "1c7f…", "label": "T2", "seats": 4, "state": "AVAILABLE" },
    { "id": "2d8a…", "label": "T3", "seats": 4, "state": "TAKEN" },
    { "id": "3e9b…", "label": "T4", "seats": 8, "minPartySize": 5, "state": "TOO_LARGE" }
  ],
  "combinations": [
    { "id": "9a1b…", "name": "T5 + T6", "tableIds": ["4fa0…", "5ab1…"], "seats": 6, "state": "AVAILABLE" }
  ]
}
```

States: `AVAILABLE`, `TOO_SMALL`, `TOO_LARGE`, `TAKEN`, `INACTIVE`.

### `POST /restaurants/{slug}/bookings`

Creates an online booking in `PENDING_VERIFICATION` and emails a code (FR-04). Exactly one of `tableId` and `combinationId` is required.

```http
POST /api/v1/restaurants/cantina-da-praca/bookings
Idempotency-Key: 4c2f8a1e-5b6d-4e7f-8a9b-0c1d2e3f4a5b
Content-Type: application/json
```

```json
{
  "startsAt": "2026-11-21T19:30:00-03:00",
  "partySize": 4,
  "tableId": "1c7f…",
  "combinationId": null,
  "guest": {
    "firstName": "Ana",
    "lastName": "Souza",
    "email": "ana@example.com",
    "phone": "+5511999998888"
  },
  "notes": "Aniversário"
}
```

`201 Created`, `Location: /api/v1/bookings/7d3e…`

```json
{
  "id": "7d3e…",
  "status": "PENDING_VERIFICATION",
  "holdExpiresAt": "2026-11-12T10:15:00-03:00",
  "verification": { "sentTo": "a***@example.com", "expiresAt": "2026-11-12T10:10:00-03:00" }
}
```

Validation: `partySize` 1–`maxPartySize`; names 1–100 characters; email valid, ≤ 255; phone in E.164 format; `notes` ≤ 500 characters.
Errors: `TABLE_NOT_AVAILABLE`, `OUTSIDE_OPENING_HOURS`, `INVALID_SLOT`, `LEAD_TIME_NOT_MET`, `TOO_FAR_IN_ADVANCE`, `PARTY_SIZE_NOT_ALLOWED`, `TOO_MANY_ACTIVE_BOOKINGS`.

### `POST /bookings/{bookingId}/verification`

```json
{ "code": "482913" }
```

`200 OK` with the [booking representation](#booking-representation) (`status: BOOKED`). The booking-received email with the management link is sent. Errors: `INVALID_CODE` (with `attemptsRemaining`), `VERIFICATION_EXPIRED`, `RATE_LIMITED`.

`POST /bookings/{bookingId}/verification/resend` takes no body and returns `202 Accepted`.

## Customer booking management

All endpoints accept either `X-Booking-Token` (management link) or a customer session for the booking's customer.

### Booking representation

`GET /api/v1/bookings/{bookingId}`

```json
{
  "id": "7d3e…",
  "restaurant": { "id": "c1d2…", "slug": "cantina-da-praca", "name": "Cantina da Praça", "timeZone": "America/Sao_Paulo" },
  "status": "BOOKED",
  "source": "ONLINE",
  "startsAt": "2026-11-21T19:30:00-03:00",
  "endsAt": "2026-11-21T21:30:00-03:00",
  "partySize": 4,
  "tables": [{ "id": "1c7f…", "label": "T2", "area": "Varanda" }],
  "combinationId": null,
  "guest": { "firstName": "Ana", "lastName": "Souza", "email": "ana@example.com", "phone": "+5511999998888" },
  "notes": "Aniversário",
  "rescheduleCount": 0,
  "confirmationDeadline": "2026-11-21T07:30:00-03:00",
  "allowedActions": ["CONFIRM", "CANCEL", "RESCHEDULE"],
  "createdAt": "2026-11-12T10:00:00-03:00",
  "updatedAt": "2026-11-12T10:03:00-03:00"
}
```

`allowedActions` lets the frontend show only the buttons valid for the current status and time.

### Actions

| Endpoint | Body | Result |
|---|---|---|
| `POST /bookings/{id}/confirm` | — | `200`, `status: CONFIRMED` (BR-32) |
| `POST /bookings/{id}/cancel` | `{ "reason": "optional text" }` | `200`, `status: CANCELLED_BY_CUSTOMER` (BR-35) |
| `POST /bookings/{id}/reschedule` | `{ "startsAt": "…", "partySize": 4, "tableId": "…" }` (or `combinationId`) | `200`, `status: BOOKED`, `rescheduleCount` + 1 (BR-36, BR-38). Same validation and errors as creation. |

## Customer history

1. `POST /customer-auth/code` with `{ "email": "ana@example.com" }` → `202 Accepted`. The response is the same whether or not the email has bookings, so emails cannot be enumerated.
2. `POST /customer-auth/token` with `{ "email": "ana@example.com", "code": "193847" }` → `200` with `{ "accessToken": "…", "expiresIn": 1800 }`.
3. `GET /me/bookings?when=upcoming|past&page=0&size=20` → paginated list of booking representations from all restaurants.

## Staff authentication

### `POST /auth/login`

```json
{ "email": "owner@cantina.com.br", "password": "…" }
```

`200 OK` (and `Set-Cookie: refresh_token=…; HttpOnly; Secure; SameSite=Strict; Path=/api/v1/auth`)

```json
{
  "accessToken": "eyJ…",
  "expiresIn": 900,
  "user": {
    "id": "e5f6…",
    "firstName": "Carla",
    "lastName": "Lima",
    "platformAdmin": false,
    "memberships": [{ "restaurantId": "c1d2…", "restaurantName": "Cantina da Praça", "role": "OWNER" }]
  }
}
```

Errors: `401 UNAUTHENTICATED` (same message for unknown email and wrong password), `429 RATE_LIMITED`.

`POST /auth/refresh` rotates the cookie and returns a new access token. `POST /auth/logout` revokes it. `GET /auth/me` returns the `user` object.

## Admin endpoints

### `PATCH /admin/restaurants/{restaurantId}`

Updates the profile and/or [settings](business-rules.md#restaurant-settings). Example:

```json
{ "settings": { "bookingDurationMinutes": 90, "turnoverBufferMinutes": 10 } }
```

### `PUT /admin/restaurants/{restaurantId}/opening-hours`

Replaces the weekly schedule. `dayOfWeek` is ISO (1 = Monday … 7 = Sunday); a closing time not after the opening time means "next day".

```json
{
  "ranges": [
    { "dayOfWeek": 2, "opensAt": "12:00", "closesAt": "15:00" },
    { "dayOfWeek": 2, "opensAt": "19:00", "closesAt": "23:30" },
    { "dayOfWeek": 6, "opensAt": "19:00", "closesAt": "01:00" }
  ]
}
```

### `POST /admin/restaurants/{restaurantId}/tables`

```json
{
  "label": "T12",
  "areaId": "a1b2…",
  "seats": 4,
  "minPartySize": 1,
  "shape": "SQUARE",
  "position": { "x": 120, "y": 340, "width": 60, "height": 60, "rotation": 0 }
}
```

Positions are in floor-plan units (the frontend scales them).

### `GET /admin/restaurants/{restaurantId}/bookings`

Filters: `from`, `to` (required, max 92 days apart), `status` (repeatable), `areaId`, `source`, `q` (guest name, email or phone). Returns paginated booking representations including contact data.

### `POST /admin/restaurants/{restaurantId}/bookings`

Phone or walk-in booking (FR-29, BR-31). Lead time, max advance and max party size do not apply; all other availability rules do.

```json
{
  "source": "PHONE",
  "startsAt": "2026-11-12T20:00:00-03:00",
  "partySize": 2,
  "tableId": "1c7f…",
  "guest": { "firstName": "João", "lastName": "Pereira", "email": null, "phone": "+5511988887777" },
  "notes": "Cadeira para bebê"
}
```

Returns `201` with `status: CONFIRMED` (`PHONE`) or `COMPLETED` (`WALK_IN`).

### Booking actions (staff)

| Endpoint | Body | Result |
|---|---|---|
| `POST …/bookings/{id}/cancel` | `{ "reason": "Restaurant closed for private event" }` (required) | `CANCELLED_BY_RESTAURANT`; customer emailed |
| `POST …/bookings/{id}/reschedule` | same as customer reschedule | `CONFIRMED` (BR-37) |
| `POST …/bookings/{id}/check-in` | — | `COMPLETED` (BR-39) |
| `POST …/bookings/{id}/no-show` | — | `NO_SHOW` (BR-40) |

`GET …/bookings/{id}` also returns `history`: the list of status changes and reschedules with actor and reason (BR-42).

### `GET /admin/restaurants/{restaurantId}/bookings/stats`

```json
{
  "from": "2026-11-01",
  "to": "2026-11-30",
  "days": [
    {
      "date": "2026-11-21",
      "bookings": 42,
      "covers": 131,
      "byStatus": { "CONFIRMED": 30, "BOOKED": 4, "CANCELLED_BY_CUSTOMER": 5, "AUTO_CANCELLED": 2, "NO_SHOW": 1 },
      "bySource": { "ONLINE": 35, "PHONE": 5, "WALK_IN": 2 },
      "rescheduled": 6
    }
  ]
}
```

### Members

`POST /members` with `{ "email": "host@cantina.com.br", "role": "HOST" }` adds an existing user or invites a new one (email with a set-password link). `PATCH /members/{userId}` changes the role; `DELETE` removes the membership (`409 LAST_OWNER` if it would leave no Owner).

## Platform endpoints

`POST /platform/restaurants`

```json
{
  "name": "Cantina da Praça",
  "slug": "cantina-da-praca",
  "timeZone": "America/Sao_Paulo",
  "ownerEmail": "carla@cantina.com.br"
}
```

Creates the restaurant with default settings and invites the Owner.

## Changes from the first draft

| First draft | New design | Why |
|---|---|---|
| `POST /reservation` | `POST /restaurants/{slug}/bookings` | Plural nouns, "booking" naming, multi-restaurant. |
| `PUT /reservation/{id}/reschedule`, `/cancel`, `/confirm` | `POST /bookings/{id}/reschedule`, `/cancel`, `/confirm` | They are actions, not full replacements. |
| `GET /reservation/status` | `GET /bookings/{id}` | The booking must be identified; status is part of the representation. |
| `POST /reservation/{id}/verify` | `POST /bookings/{id}/verification` + `/resend` | Two steps: send and check the code. |
| `GET /table`, `GET /table/availability` | `GET /restaurants/{slug}/floor-plan`, `/availability/slots`, `/availability/tables` | Separate list of times from the seat map. |
| `/manager/auth/login` (no method) | `POST /auth/login`, `/refresh`, `/logout` | JWT with refresh tokens. |
| `GET /manager/reservation` | `GET /admin/restaurants/{id}/bookings` | Restaurant-scoped admin API. |
| `PATCH /manager/table/{id}/deactivate` | `POST /admin/restaurants/{id}/tables/{tableId}/deactivate` + `/activate` | Reactivation was missing. |
| `POST/PUT /manager/table/register/` | `POST /admin/restaurants/{id}/tables`, `PATCH …/tables/{tableId}` | One method per operation. |
| — | Customer history, staff bookings, check-in, no-show, stats, members, audit log, opening hours, closures, areas, combinations | New requirements. |
